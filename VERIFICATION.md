# Verification — redesign v2

Executed in the repository on Node v22.23.1 with installed Playwright, Chromium and axe tooling outside the entry. The test server is PORT=4179 node serve.mjs. Its main.js SHA-256 was compared with this checkout before browser testing. Port 4178 was found to serve different bytes and was left alone; the existing 4186 server and tunnel were not changed.

Results:

- node --test tests/*.test.mjs: 10 passing tests. Covers ETag/304, shared requests, stale expiry/recovery, 429 and 503 cooldown, cache eviction/null rejection, route and URL safety, compact rows and opening/deadline validity.
- node tests/browser.mjs: 60 assertions, including URL filters/sort/pagination, saved items, theme persistence, comparison capped at three, all five functional tabs, safe Markdown tables/code/lists, inert HTML and unsafe links, projected reward joining, provisional judge records, keyboard focus after tab navigation, four routes at 360/390/768/1280px, malformed/null/network failures and recovery.
- node tests/live.mjs: all four real public views loaded; 16 combinations of route, mobile/desktop and light/dark passed console and page-overflow checks, plus four rich detail tabs. No intercepted live responses.
- node tests/accessibility.mjs: 16 axe scans across four live routes, two themes and two viewport widths returned zero WCAG 2 A/AA and WCAG 2.1 AA violations. Eight route/viewport overflow checks and two skip-link/focus checks also passed: 26 checks total. Automated scans are not an exhaustive accessibility audit.
- node tests/capture.mjs: exactly three genuine live API viewport screenshots, with provenance in shots.json. Desktop light board 1280×900, dark bounty 1280×900, mobile leaderboard 390×844. Byte sizes: 144,798; 204,711; 60,419 respectively. Each is below 262,144 bytes and has a long side at most 1280px.
- node tests/package.mjs: two independent offline runs produced identical relative paths and SHA-256 hashes for all 11 files. Seven local assets total 44,512 raw bytes and 15,706 gzip level-9 bytes. Dossier: 593,218 bytes. All seven local assets are eager-loaded, so this is the complete first-load local code/style/HTML budget; live API JSON and lazy remote image bytes are additional. The supplied server does not negotiate gzip, so gzip figures describe compression potential, not observed HTTP transfer from that server.

Defects found and corrected during this session: a profile-expression parse error, a footer link relying on color, a null escrow link exposed by absent-URL resolution, a stale test readiness flag between hash changes, and ambiguous legacy live-test selectors after adding the persistent board. Rich Markdown tests assert rendered content so an error screen cannot satisfy security checks by omission.

API evidence supports prize_rank joined to rewardsNow.place, confidence intervals and provisional judge W/D/L records. Statistical rank ranges do not change ordinal positions. Projected awards are not earned payouts. Missing data remains unknown. Source-withheld entries display that fact; no withheld archive source was fetched. Public research highlighted board/detail continuity and richer metric/reward surfaces in Potboard/Tally; competitor first-load claims remain unverified and are not benchmarks for this implementation.

Limitations: board filters/totals cover loaded records, with cursor load-more when supplied. Persistent board search/scroll is in-memory; back link state survives route changes but not a fresh reload. Rows paginate rather than virtualize. Profile history is limited to the public response. Markdown is a small safe subset, without nested-list parsing or full CommonMark conformance. Images are limited to make.fun API avatar/submission paths and may be absent or unavailable. Cache is in-memory, data refresh is explicit or navigation-driven, and the cache status describes the most recent API operation rather than per-panel provenance. No account writes, payments or submission occurred.
