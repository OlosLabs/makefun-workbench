# Design

Workbench uses original CSS informed by Primer's public color-usage and typography guidance: semantic background, foreground and border tokens; system sans fonts; compact readable hierarchy. Light mode uses white and subtle gray surfaces. Dark mode uses near-black and charcoal surfaces with separately chosen text, border and blue-link tokens. Green identifies an open bounty. This project has no GitHub affiliation and imports no Primer runtime.

The global header reads as an owner/workspace breadcrumb. The board uses compact issue-like rows with category, status, title, entry count, local save and comparison controls, pot, fee and time remaining. Search, filters and sorting remain URL-backed. The deadline agenda excludes expired items. Text metadata is at least 12px, body text is 14px on desktop and 16px on mobile.

On desktop, a searchable bounty list stays beside the selected public view. It remains mounted during detail-to-detail navigation, preserving its search and scroll position. The right pane contains the selected view. On mobile the list collapses and an explicit back link restores the previous board URL, including filters and pagination. Full page reloads retain URL state and local preferences, but do not retain a previous in-memory board URL.

Bounty tabs use ordinary shareable links and an underline for the current page. Overview renders the brief; Rules shows API rules and resolution criteria; Rewards shows base, fee share and projected allocation; Entries provides paginated public metadata and API artifact previews; Standings embeds the metric-aware leaderboard. The About sidebar presents sponsor, skills, dates, requirements and public escrow information when returned.

Leaderboard ordinal ranks remain distinct from statistical rank ranges. Metric direction comes from column metadata. Judge millionths are shown as percentages, intervals retain their confidence label, and awards join prize_rank to rewardsNow.place. Provisional records and projected amounts are explicitly labeled. Profiles show supplied avatars, records, safe public links, solutions and artifacts without synthetic activity grids or missing-value zeroes.

Remote text is constructed with DOM text nodes. The small Markdown renderer supports headings, ordered and unordered lists, emphasis, links, fenced code and tables; raw HTML stays inert. Images accept only API-provided make.fun avatar/submission paths, set anonymous CORS before src, reserve dimensions and load lazily. Every control has visible keyboard focus. Axe scans cover both themes and desktop/mobile; they supplement manual semantic design and executable behavior checks.

Public research identified board/detail continuity and richer reward/metric surfaces in Potboard and Tally descriptions and public screenshots. Those observations informed priorities. Competitor byte claims were not independently verified and their withheld sources were not accessed. Our measured asset total is documented in VERIFICATION.md.
